# AI 对 Godot 的完整操作能力

状态：0.2 在 macOS / Godot 4.7.2 上完成九类工作流的实现与样本验证，交付待用户验收；不等于所有引擎操作和平台已穷尽测试。来源：2026-10-12 月汐明确要求。实际证据见 [验证记录](validation.md)。

## 总目标

AI 能够对 Godot 执行任何操作：人能执行的，AI 都能执行；也能完成手工难以完成的批量生成、遍历检查、精确修改和自动实验。

这意味着新任务出现时，AI 能自己发现入口、编写并执行代码、观察结果和修复错误，不需要维护者先给 REPL 添加一个专用命令。接口清单不能成为能力上限。任意代码执行是必要基础，但它本身不构成完整操作能力的验收通过。

“超出手工能力”指规模、速度、精度和自动化组合，不意味着绕过操作系统权限、引擎能力或用户授权。

## 验收单位：一个完整任务

每个任务都要走完：发现当前工程与可用接口 → 执行 → 查询状态或读取产物 → 判断是否符合预期 → 必要时修复 → 保存可复现结果。不能仅以请求返回 OK 判断成功。

验收任务由验收方在执行时给出，允许 AI 阅读文档、反射接口和临时编写脚本。实现中不得预埋该任务的专用处理；不要求所有任务只能通过 GDScript 完成，但必须记录实际使用的通道和外部依赖。

## 必须覆盖的工作流

| --- | --- | --- |
| 自主发现 | 列出当前对象、属性、方法、信号和编辑器服务，选择合适入口完成未预设操作 | ClassDB 与对象反射已测；全部新增任务通过通用 eval 执行，无任务专用端点 |
| 编辑器操作 | 创建、修改、保存并重新打开场景；完成可撤销操作并验证撤销、重做 | 创建、UndoRedo、保存、重启编辑器及重开回读已测 |
| 工程与资源 | 新建工程，修改脚本、设置与输入映射，生成或导入资源并确认可加载 | 空工程、SVG 导入、项目脚本、动画资源、持久输入映射已测 |
| 运行时 | 查询与修改真实对象、调用项目逻辑、等待帧与信号、模拟输入并验证行为 | 按键改变项目分数、鼠标触发按钮、动画完成信号与物理射线已测 |
| 观察结果 | 读取日志、错误、对象状态和真实画面，区分执行成功与效果正确 | 日志、错误、状态及截图已测 |
| 生命周期 | 启动、停止、重启、重连，处理卡死或崩溃并从保存的工程继续 | 进程控制 CLI、同步死循环恢复、进程意外被杀恢复、会话重新连接已测；不接管其他进程 |
| 构建与交付 | 设置导出配置、构建产物、启动产物并验证功能 | 官方 macOS 模板导出应用并运行，验证输入、资源和开发通道关闭 |
| 脚本接口之外 | 对选定的界面专属或未暴露功能，实际验证界面控制、扩展或其他可执行路径 | 编译、加载、执行、卸载 C GDExtension 已测；宿主 cua_repl 操作原生菜单已测 |
| 超出手工规模 | 批量生成与修改大量对象或资源，自动检查全部结果；中断后可追踪已完成范围 | 生成并逐个核对一万个节点；三千节点后卡死、重启续作，已完成批次哈希不变 |

以上是必测维度，不是操作白名单。动画、物理、UI、渲染等领域任务应作为跨维度样本持续补充。发现没有可用执行路径的操作时，记录为能力缺口并补齐；不能通过缩小验收口径把它排除。

## 执行路径

REPL 负责编辑器与游戏进程内的通用代码执行。工程文件与进程由外部工具操作；界面专属操作可用桌面控制；未向脚本暴露的原生能力需要评估扩展或引擎源码路径。每条补充路径都必须有实际验证，不能把理论上可调用当作已经实现。

同步死循环堵塞主线程时，进程内 REPL 无法自行救活。完整方案必须由进程外控制恢复，并说明未保存改动与内存状态的处理结果。恢复不等于自动回滚。

## 通过标准与报告方式

所有必测维度都要有可复现证据，验收方给出的跨领域新任务能在无需增加专用接口的前提下完成，已发现的阻断缺口已解决，才可申请该版本的完整验收。

有限测试不能证明所有未来任务都必然成功。报告必须写明版本、平台、权限、已测范围与剩余缺口。0.1 仅为基础通道；0.2 的表中证据来自新增真实运行测试，不是追认旧测试。用户或独立验收方仍可提供新的跨领域任务；出现阻断即作为缺口继续修复，不能用当前样本排除它。
